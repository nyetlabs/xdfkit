# Canonical model

The format-neutral model every reader converts into and every writer converts out of. Its JSON form is the interchange format. Implemented in `model/` for KP in both directions, for XDF (with its metadata file, `stamp-and-metadata.md`), and for A2L and DAMOS read into schema 1.

## Conventions

- Schema: generated from the Go types in `model/` (struct tags `json`, `doc`, `enum`, `pattern`) by xdfkit's own generator, and committed as `model/schema.json` (JSON Schema draft 2020-12). A test fails when the committed file differs from the generated one; `make schema` rewrites it. Tests also validate every ecuxplot pack's model against the committed schema (`github.com/santhosh-tekuri/jsonschema`, used in tests only).
- Scope: schema 1 holds what the readers emit. Axes, conversions and record layouts are inlined on each object. Shared lists and image identity are not in schema 1. It grows by adding optional fields; a breaking change bumps the schema version. `format-matrix.md` lists what schema 1 holds next to the target, which is the plan, not current capability.
- Addresses are hex strings, `"0x13D52"`: written in uppercase, read in either case, at most 8 digits.
- Object `key` is the source id. A blank id leaves the key blank: an empty key is allowed, and nothing invents a placeholder for it. A repeated key is allowed. The source id stays in `id`. KP ids aren't unique: 8D0907551G repeats 240 of them and 8D0907551M uses `-` 35 times. The XDF title holds the first word of `id`; the XDF metadata file keys on the XDF uniqueid and restores `key` and the full `id` (`stamp-and-metadata.md`).
- JSON is written in canonical form (`jq -S .`, typed numbers) with the edit stamp (`stamp-and-metadata.md`).

## Document

- `schema`: `xdfkit-model/1`.
- `provenance`: source `format` (`kp`; `xdf` for an XDF read without its metadata file; `a2l`; `damos`; `image` for maps located in a flash image by a program, me7info, with the image's `sha256`), the definitions' `origin` (`damos`, `a2l`, `manual`, or `auto` for format `image`), original `file` name, and its `sha256`. `verified` is set when a person checked every definition against the image. An auto definition checked against another one carries `reference`: its `origin` (`damos`, `a2l`, or `manual`), `file`, `sha256`, `agree` (names at the same address, and names in the reference), `except` (reference names known to sit elsewhere, such as ESKONF), and `unreferenced` (located names the reference does not list). `Reference.Agreed` is true when every reference name outside `except` agrees. The writing tool and version are in the stamp. `subset` (`kind` `tuner`, and `table`, the category table's SHA-256) marks a definition cut down from the original's: `Model.Tuner` sets it, the XDF writer adds an `xdfkit-subset:` line to the header description (read back without the metadata file too), and loading a subset warns.
- `Model.Tuner(table)` (`xdfkit --tuner categories.json`, `ConvertRequest.Tuner`): keeps the objects named in a `CategoryTable` and the objects their image axes point at (at the axis address, or before its header), replaces the categories with the table's, and sets `provenance.subset`. It needs the model's provenance. `Model.Categorize(table, rest)` files the same way but keeps every object, the rest under `rest` (me7info's full XDF uses `Other`). A category table is schema 2 (`categories.schema.json`): `categories` maps each category name to the map names filed under it, and a name is listed once. `ParseCategoryTable` rejects unknown keys, an empty table, an empty name, and a name listed twice.
- `project`: `name`, `version`.
- `categories`: `id`, `name` (KP folders).
- `objects`: in source order. Each has `key`, `id`, `description`, `comment`, `categories` (ids), `shape` (`value`, `1d`, `2d`), `inverse` (KP "2d Inverse", meaning unconfirmed), `vislevel` (TunerPro XDF visibility level; 1 is the WinOLS map-list marker / KP `Marked`; 0 is unmarked and written as XDF level 2), `address`, `rows`, `cols`, `data` (`bits` 8/16/32, `endian` big/little for wider cells, `signed`, `float`), `value` (`description`, `units`, `precision`, `conversion`: `factor`, `offset`, `reciprocal`, and optional `min` and `max`), `view` (`base`, `difference`, `percent`), the axes `x` and `y`, and optional `alternates`.
- `min` and `max` are the lowest and highest value shown (display units). Omitted when the source has none. The XDF writer emits them only when both are set, ordered low to high. KP stores a raw typed pair per element width (`kp-format.md`); read and write convert with the map conversion. A missing model pair writes the default raw span; a KP default pair is omitted from the model. The XDF reader also drops a min and max that are only the conversion of the raw endpoints (`xdf/`, `limits`).
- `view.base` is 10, 16 or 2. Omitted is written as 10. WinOLS crashes when a map whose base is 0 is opened. A defined axis with no storage is written as an 8-bit ordinal.
- `alternates` (`Alternate`) are other displays of the same cells: each has its own id, description, categories, value and view, and optional axis display on `x` and `y`. Address and storage stay on the object. `xdfkit merge --smart` adds one when two objects share a raw layout and differ in units or conversion (`design.md`). The XDF writer emits one table per alternate (`stamp-and-metadata.md`).
- Axes: `source` is `image` (read from the image), `ordinal` (1, 2, 3), `editable` (KP "Free editable") or `unknown` (an unnamed KP datasource, written back as ordinal). Image axes also have `stored` (`absolute`; `add`, `subtract`, and `backwards`, the confirmed formulas in `kp-format.md`), `address` and `data`. Editable axes carry `data` (element type) and `values` (display units); the KP writer packs them as consecutive elements zero-padded to 4 bytes per point, and the XDF writer emits them as labels. Every axis has `value` and `view`, `mirror` (WinOLS shows it descending) and, when WinOLS has one, `signature` (the KP `SignatureByte` (unconfirmed): a marker byte before the axis data).
- Names are format-neutral English; each writer maps them to its format's names.
- `image`, the identity of the flash image (part number, version, Bosch ident, SHA-256), is planned and not in schema 1 yet.
- A conversion `/REP 0, B, C, 0` (phys = (B / C) / raw; the `zk*` time constants and `rfak*` factors) sets `reciprocal` with factor B/C and offset 0. The KP flag is the same formula: on `06A906032HF` the `/SPW` low field is that factor divided by the full-scale raw value (`25.6/255` and `6553.6/65535`). CM and S store the factor. WinOLS's DAMOS import writes factor 1 for that form. DAMOS `/REP` is internal = (A * phys + B) / (C * phys + D): C = 0 and D ≠ 0 is linear (phys = (D * raw − B) / A when A ≠ 0). Anything else that is not the reciprocal form warns and is stored as factor 1. A2L `RAT_FUNC` `COEFFS` are ASAM MCD-2 MC as internal = f(phys): int = (a*phys² + b*phys + c) / (d*phys² + e*phys + f). The model stores phys = factor*raw + offset. Linear (a = d = e = 0, b and f nonzero) is factor f/b and offset −c/b; reciprocal (a = b = d = f = 0, e nonzero) is factor c/e. That matches KP and XDF on Bosch ME7 exports.
- ME7 record layout, read by the DAMOS reader and by an A2L `RECORD_LAYOUT` whose counts are bytes. The `/SPZ` address (ECU address minus 0x800000) is the record start. Values (type 1), curves and maps on shared axes (7, 8), fixed-axis curves and maps (4, 5) and value blocks (13) start there. A record with inline axes (2 curve, 3 map, 6 axis-point table) holds one count per axis, then the axes, then the values, and every 16-bit field starts at an even address, with a pad byte before it when needed: a curve with an 8-bit axis of four points and 16-bit values is count, four axis bytes, pad, values. Each count is a byte, except an inline map whose axes are both 16-bit: those two counts are 16-bit little-endian (KFMIRL on 06A906032S and 8D0907551M-0002 starts with the row count and the column count). `/FKX` is the declared length (a curve's columns, a map's rows); `/FKY` is a map's columns. An inline map stores the row axis (`/SPX`) first and the column axis (`/SPY`) second. A curve or map on a shared axis (7, 8) keeps its values at the record start. The last number on its `/SPX` (and `/SPY` for a map) is the `/SPZ` index of an axis-point table (type 6); the map copies that table's axis-point address, width, conversion and `/FKX` length. Confirmed against the images of 06A906032HF, 06A906032S and 8D0907551M-0002 (`/SPX` and `/SPW` give the widths). An A2L layout whose count fields are wider than a byte is walked in ASAM position order with `MOD_COMMON` alignment, not this one-byte rule. `BYTE_ORDER MSB_LAST` is little-endian (ASAM). A DAMOS file has no byte-order field; the reader stores little-endian and warns once.

## KP output

The model JSON holds no format-specific residue: no `sources` blocks and no KP-only fields (view state, unconfirmed fields). Values that are understood become model fields; the rest stay in the KP file.

- KP output takes every field the model doesn't carry from a template KP: the file header and trailing data from the template, and each map's KP-only fields from the template's map with the same `key` (each folder's from the folder with the same id). Copies that share a key take that residue in source order. With the file the JSON was read from as template (`xdfkit --template orig.kp in.json out.kp`), the output reproduces it (tests: v1 byte for byte, v2 except for a re-deflated zip when maps changed). A template other than the file in `provenance` gives a warning.
- Without a template, the template is an empty WinOLS 2.24 map pack (`model/empty.kp`, so the output is v2), and maps and folders take per-layout defaults from `model/kp-defaults.json`: the commonest value of each KP-only field over ecuxplot's packs (keys `v1` and `v2`) and, when regenerating with a local WinOLS 5 pack present, an `ols5` block, generated by the tests (`make schema`) and checked for drift. Defaults that are 0 or all-zero bytes are left out (fixed-length byte runs encode empty as zeros), and the `-` that WinOLS writes as the description and units of unused axis slots is in the code. Round numbers (0x100 and up, one hex digit then zeros, or all Fs) are written there as hex strings (`"0x100000"`, `"0xFFFF"`). The map's image size has no model field yet and defaults to 0x100000. Maps and folders that aren't in the template get the same defaults. Some fields are derived from the model instead: the element widths, the end address (start + byte length), `addr2` (the start address in most packs), the stored dimensions (`StoredCols`, `StoredRows`), and, when the map did not come from a template, the value-range pair for its width (`kp-format.md`). Default-filled KP reads back to the same model (tests), and WinOLS 2.24 imports it and displays the maps as defined (8D0907551M from v2 and 8D0907551G from v1, both also after lint fixes on the JSON; confirmed).
- When a model field is edited, the KP record takes the new value, unless the template's record holds a value the model can't represent for that field.
