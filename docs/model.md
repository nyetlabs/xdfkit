# Canonical model

The format-neutral model every reader converts into and every writer converts out of. Its JSON form is the interchange format and the corpus format (`corpus.md`). Implemented in `model/` for KP in both directions and for XDF (with its metadata file, `stamp-and-metadata.md`); A2L and DAMOS come later and extend it.

## Conventions

- Schema: generated from the Go types in `model/` (struct tags `json`, `doc`, `enum`, `pattern`) by xdfkit's own generator, and committed as `model/schema.json` (JSON Schema draft 2020-12). A test fails when the committed file differs from the generated one; `make schema` rewrites it. Tests also validate every ecuxplot pack's model against the committed schema (`github.com/santhosh-tekuri/jsonschema`, used in tests only).
- Scope: the schema carries what the implemented readers need, in a structure ready for A2L (objects and categories referenced by id; shared axes, conversions and record layouts get their own top-level lists when A2L arrives). It grows by adding optional fields; a breaking change bumps the schema version. `format-matrix.md` lists what schema 1 holds next to the target, which is the plan, not current capability.
- Addresses are hex strings, `"0x13D52"`: written in uppercase, read in either case, at most 8 digits.
- Object keys: every object has a `key` unique within the file. It is the source's id, with `#2`, `#3` appended to repeats in source order (`KFZW 16#2`, `-#35`), or `obj-N` (N its 1-based position) when the id is blank. The source's own id stays in `id`. KP ids aren't unique: 8D0907551G repeats 240 of them and 8D0907551M uses `-` 35 times. The XDF title holds the first word of `id`; the XDF metadata file keys on the XDF uniqueid and restores `key` and the full `id` (`stamp-and-metadata.md`).
- JSON is written in canonical form (`jq -S .`, typed numbers) with the edit stamp (`stamp-and-metadata.md`).

## Document

- `schema`: `xdfkit-model/1`.
- `provenance`: source `format` (`kp`; `xdf` for an XDF read without its metadata file; `image` for maps located in a flash image by a program, me7info, with the image's `sha256`), the definitions' `origin` (`damos`, `a2l` or `hand`, `corpus.md`; `located` for format `image`, never a corpus source), original `file` name, and its `sha256`. The writing tool and version are in the stamp. `subset` (`kind` `tuner`, and `table`, the category table's SHA-256) marks a definition cut down from the original's, which must never replace it in the corpus: `Model.Tuner` sets it, the XDF writer adds an `xdfkit-subset:` line to the header description (read back without the metadata file too), loading a subset warns, and `publish/import-incoming.sh` refuses one.
- `Model.Tuner(table)` (`xdfkit -tuner categories.json`, `ConvertRequest.Tuner`): keeps the objects named in a `CategoryTable` (`corpus.md`; `ParseCategoryTable` rejects unknown keys) and the objects their image axes point at (at the axis address, or before its header), replaces the categories with the table's, and sets `provenance.subset`. It needs the model's provenance. `Model.Categorize(table, rest)` files the same way but keeps every object, the rest under `rest` (me7info's full XDF uses `Other`).
- `project`: `name`, `version`.
- `categories`: `id`, `name` (KP folders).
- `objects`: in source order. Each has `key`, `id`, `description`, `comment`, `categories` (ids), `shape` (`value`, `1d`, `2d`), `inverse` (KP "2d Inverse", meaning unconfirmed), `address`, `rows`, `cols`, `data` (`bits` 8/16/32, `endian` big/little for wider cells, `signed`, `float`), `value` (`description`, `units`, `precision`, `conversion`: `factor`, `offset`, `reciprocal`), `view` (`base`, `difference`, `percent`), and the axes `x` and `y`.
- Axes: `source` is `image` (read from the image), `ordinal` (1, 2, 3), `editable` (KP "Free editable"; where WinOLS stores those values isn't known) or `unknown` (an unnamed KP datasource, written back as ordinal). Image axes also have `stored` (`absolute`; `subtract`, the confirmed formula in `kp-format.md`; `add` and `backwards`, semantics unknown), `address` and `data`. Every axis has `value` and `view`, `mirror` (WinOLS shows it descending) and, when WinOLS has one, `signature` (the KP `SignatureByte`, likely the WinOLS script's `SignaturByte`: a marker byte before the axis data).
- Names are format-neutral English; each writer maps them to its format's names (WinOLS script properties in `winols-script.md`).
- `image`, the identity of the flash image (part number, version, Bosch ident, SHA-256), is planned for the corpus and not in schema 1 yet.

## KP output

The model JSON holds no format-specific residue: no `sources` blocks and no undecoded KP fields. Values that are understood become model fields; the rest stay in the KP file.

- KP output takes every field the model doesn't carry from a template KP: the file header and trailing data from the template, and each map's undecoded fields from the template's map with the same `key` (each folder's from the folder with the same id). With the file the JSON was read from as template (`xdfkit -template orig.kp in.json out.kp`), the output reproduces it (tests: v1 byte for byte, v2 except for a re-deflated zip when maps changed). A template other than the file in `provenance` gives a warning.
- Without a template, the template is an empty WinOLS 2.24 map pack (`model/empty.kp`, so the output is v2), and maps and folders take per-layout defaults from `model/kp-defaults.json`: the commonest value of each undecoded field over ecuxplot's packs, generated by the tests (`make schema`) and checked for drift. Defaults that are 0 or all-zero bytes are left out (fixed-length byte runs encode empty as zeros), and the `-` that WinOLS writes as the description and units of unused axis slots is in the code. Round numbers (0x100 and up, one hex digit then zeros, or all Fs) are written there as hex strings (`"0x100000"`, `"0xFFFF"`). The map's image size has no model field yet and defaults to 0x100000. Maps and folders that aren't in the template get the same defaults. Some fields are derived from the model instead: the element widths, the end address (start + byte length), `addr2` (the start address in most packs) and the stored dimensions (`YUnk06`, `YUnk0A`). Default-filled KP reads back to the same model (tests), and WinOLS 2.24 imports it and displays the maps as defined (8D0907551M from v2 and 8D0907551G from v1, both also after lint fixes on the JSON; confirmed).
- When a model field is edited, the KP record takes the new value, unless the template's record holds a value the model can't represent for that field.
